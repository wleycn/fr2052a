## 1.1 设计目标

1. 支持 FR 2052a 全 Section A-K 的数据采集、标准化、汇总、报送。
2. 支持合并口径与重要实体子公司口径。
3. 支持批处理 T+1 报送，同时支持 Kafka 实时流动性预警。
4. 支持 Iceberg Time Travel，满足监管审计与重述。
5. 支持 GL 对账、数据质量校验、PII 脱敏、业务血缘。
6. 可在 2 台服务器上稳定演示。

## 1.2 设计原则

| 原则 | 说明 |
|---|---|
| 分层建模 | ODS/OWD/OWS/ADS 四层，职责分离 |
| 批流一体 | Kafka 实时接入，Iceberg 统一存储，Spark/dbt 批流处理 |
| 双轨制 | Core 纯批处理稳定演示；Advanced 流批一体展示技术深度 |
| 合规优先 | GL 对账、监管映射、重述、审计、脱敏 |
| 可观测 | Airflow SLA、Great Expectations、DataHub、Prometheus/Grafana |
| 安全默认 | 密钥不入库、TLS/SASL、RBAC、行列权限 |
| 避免过度设计 | 演示环境轻量化，HDFS 用 MinIO 替代，ZK 用 KRaft 替代 |

## 1.5 双轨制架构

### Core 核心演示版
- 栈：PostgreSQL + dbt + Great Expectations + Airflow LocalExecutor。
- 重点：FR 2052a 模型、到期分桶、HQLA、GL 对账、GE 校验、Airflow 调度。
- 数据量：10 万 - 100 万行。
- 必须 100% 稳定运行。

### Advanced 扩展版
- 栈：Kafka + MinIO + Iceberg + Spark。
- 重点：实时流动性预警、Time Travel、Schema Evolution、海量压力测试。
- 演示方式：Jupyter Notebook + 架构图 + 按需启动。

## 1.6 技术选型

| 能力 | 选型 |
|---|---|
| 调度 | Airflow |
| 转换 | dbt-postgres + dbt-spark |
| 数据质量 | Great Expectations + dbt tests |
| 元数据/血缘 | DataHub + dbt docs |
| 消息 | Kafka KRaft |
| 对象存储 | MinIO |
| 开放表格式 | Iceberg |
| 计算 | Spark Standalone / DuckDB 备用 |
| 结果库 | PostgreSQL |
| 脱敏 | dbt macro + PG Security Barrier View |
| 监控 | Prometheus + Grafana + Airflow SLA |

## 1.7 非功能需求

| 类型 | 要求 |
|---|---|
| 性能 | ADS 报表查询秒级；Iceberg 海量明细 Spark 分布式计算 |
| 可用性 | Core 版每日 T+1 08:00 ET 前完成报送 |
| 可审计 | 每层保留 source_system、source_record_id、etl_load_timestamp |
| 可追溯 | DataHub 展示技术血缘 + 监管规则映射 |
| 安全 | PII 脱敏、RBAC、行列权限、TLS/SASL、密钥管理 |
| 可恢复 | PG 每日备份，MinIO 版本化，Iceberg snapshot 保留 |
| 可扩展 | Schema Evolution、新增 Section/字段无需重构全链路 |
