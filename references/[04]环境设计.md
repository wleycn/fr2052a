## 4.3 Server 1 搭建

### 目录
```bash
mkdir -p ~/fr2052a-infra && cd ~/fr2052a-infra
```

### 启动 PG、MinIO、Airflow
使用 `docker-compose-core.yml`：
- PostgreSQL：`fr2052a/secret123`，库 `fr2052a_db`。
- MinIO：`admin/password123`，端口 9000/9001。
- Airflow：LocalExecutor，初始化用户 `admin/admin`。
- 启动：
```bash
docker compose -f docker-compose-core.yml up -d
```

### 启动 DataHub
```bash
pip install acryl-datahub
datahub docker quickstart
```
访问 `http://192.168.17.22:9002`，默认 `datahub/datahub`。

### 创建 MinIO Bucket
```bash
mc alias set local http://192.168.17.22:9000 admin password123
mc mb local/fr2052a-bucket
```

## 4.8 避坑指南

1. **防火墙**：双机部署 90% 失败源于端口不通。
2. **MinIO Endpoint**：Spark 中必须用 `192.168.17.22:9000`，不能用 `localhost`。
3. **端口冲突**：Airflow 8080 与 Spark Master 默认 8080 冲突，但是它们在不同server,没有影响.
4. **DataHub 内存**：ES 调低 `-Xms1g -Xmx1g`。
5. **Kafka Listener**：正确配置 `ADVERTISED_LISTENERS`，外部用 `192.168.17.24:9094`。
6. **Iceberg 依赖**：Spark 需加载 `iceberg-spark-runtime` 和 `hadoop-aws`。
7. **密钥管理**：演示可环境变量，生产用 Vault/Docker Secrets。
8. **备份**：PG 每日 dump，MinIO 版本化，Iceberg 保留 snapshot。

## 4.9 安全与运维

- 传输：Kafka SASL/TLS、PG SSL、MinIO TLS。
- 权限：PG 角色、MinIO Policy、DataHub 角色。
- 脱敏：dbt macro + Security Barrier View。
- 审计：`audit_access_log`、`audit_change_log`。
- 监控：Prometheus + Grafana + Airflow SLA + 告警。
- 容灾：PG 主备、MinIO 多盘、Iceberg metadata 备份。

# 5. 最终建议

1. **先做 Core 版**：PostgreSQL + dbt + GE + Airflow，确保 FR 2052a 业务逻辑、GL 对账、校验、报送全部跑通。
2. **再做 Advanced 版**：Kafka + Iceberg + Spark，展示实时预警、Time Travel、Schema Evolution。
3. **治理贯穿始终**：DataHub 业务血缘、监管映射、PII 脱敏不要后补。
4. **演示故事线**：  
   “传统 T+1 报送 → 实时流动性预警 → Iceberg 审计重述 → GL 对账阻断 → DataHub 监管血缘 → 安全脱敏报送。”
5. **里程碑**：  
   - Phase 1：业务内核 + GL 对账。  
   - Phase 2：质量合规 + 监管映射 + 脱敏。  
   - Phase 3：Airflow 编排 + 重述流程。  
   - Phase 4：Kafka/Iceberg 高级演示 + DataHub。
