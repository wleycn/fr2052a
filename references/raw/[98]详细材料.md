# 一、进一步详细设计

## 1.1 领域模型与实体关系

核心实体：

| 实体 | 说明 |
|---|---|
| 法人实体 | 合并口径、重要子公司 |
| 交易对手 | 央行、主权、银行、券商、企业、零售 |
| 金融产品 | 存款、融资、回购、贷款、证券、衍生品、表外 |
| 抵押品 | HQLA L1/L2A/L2B、非 HQLA |
| 总账科目 | GL 对账 |
| 报表行项目 | FR 2052a Section / Line Item |
| 到期分桶 | O/N、1-7D、8-30D、31-90D、91-180D、181D-1Y、>1Y、OPEN |
| 数据版本 | SCD2、重述、Iceberg Snapshot |
| 校验规则 | DQ、GL、业务规则 |
| 报送文件 | XBRL/XML/CSV、回执 |

核心关系：

```text
法人实体 1--N 金融产品
交易对手 1--N 金融产品
金融产品 1--N 现金流
金融产品 N--1 抵押品
金融产品 N--1 FR 2052a Line Item
FR 2052a Line Item N--1 Section
报表 1--N 报表明细
报表 1--N 校验日志
报表 1--1 GL 对账
报表 1--N 重述日志
```

## 1.2 分层处理规则

### ODS 层
- 1:1 映射源系统。
- 不修改业务值。
- 只增加 ETL 元数据。
- 必须保留 `source_system + source_record_id`。

### OWD 层
- 清洗、去重、标准化。
- 统一币种、国家、产品、评级、行业。
- 汇率转换：`amount_usd = amount_lc * fx_rate`。
- 到期分桶：按 `report_date` 到 `maturity_date` 的剩余天数。
- 映射 FR 2052a Section / Line Item。
- 生成 SCD2 版本字段。

### OWS 层
- 按 `report_date + entity_code + section + line_item + product + counterparty + currency + maturity_bucket + purpose` 聚合。
- 计算：
  - 总余额
  - 加权平均利率
  - 加权平均到期天数
  - 预期流入/流出
  - 净现金流
  - HQLA 折扣后价值
- 必须满足：汇总金额 = SUM 明细金额，误差 < 0.01。

### ADS 层
- 完全对齐 FR 2052a。
- 生成 Section A-K。
- 生成明细行。
- 执行最终校验。
- 生成报送文件。
- 记录报送状态与回执。

## 1.3 关键映射规则

### 到期分桶

| Bucket | 最小天数 | 最大天数 |
|---|---|---|
| O/N | 0 | 0 |
| 1-7D | 1 | 7 |
| 8-30D | 8 | 30 |
| 31-90D | 31 | 90 |
| 91-180D | 91 | 180 |
| 181D-1Y | 181 | 365 |
| >1Y | 366 | 99999 |
| OPEN | NULL | NULL |

### HQLA 规则

| 等级 | 示例 | Haircut |
|---|---|---|
| Level 1 | 现金、央行准备金、国债 | 0% |
| Level 2A | 机构债、GSE | 15% |
| Level 2B | 投资级公司债、部分股票 | 50% |
| Non-HQLA | 其他 | 不纳入 |

### 现金流 Cap 规则
- 预期现金流入 <= 总现金流出的 75%。
- 若超过，按 75% 截断，并记录校验警告。

### Operational 存款
- 清算、托管、现金管理相关存款标记为 `OPERATIONAL`。
- 流出率低于 `NON_OPERATIONAL`。

## 1.4 Airflow DAG 详细设计

### DAG：`fr2052a_daily_batch`

任务顺序：

```text
check_source_arrival
  → load_ods
  → dbt_run_owd
  → dbt_run_ows
  → dbt_run_ads
  → gx_validate
  → gl_reconciliation
  → generate_submission
  → datahub_ingest
  → submit_to_fed
```

### DAG：`fr2052a_realtime_alert`
- 消费 Kafka `core_banking_txns`。
- 检测大额提款、大额贷款提取。
- 触发 LCR 红线告警。

### DAG：`fr2052a_backfill_and_restate`
- 输入：`report_date`、`entity_code`、`reason`。
- 重跑 OWD/OWS/ADS。
- 写入 `ads_restatement_log`。
- 重新执行 GX 与 GL 对账。

### DAG：`fr2052a_gl_reconciliation`
- 读取 `ods_gl_balances`。
- 与 `ows_funding_summary` 对账。
- 差异 > 阈值则失败。

### DAG：`fr2052a_submission`
- 生成 XBRL/XML/CSV。
- 提交 Federal Reserve。
- 记录回执。

## 1.5 数据质量与 GL 对账

### GL 对账表核心逻辑

```sql
SELECT
  l.report_date,
  g.credit_balance AS gl_amount,
  l.total_liability AS fr2052a_amount,
  (g.credit_balance - l.total_liability) AS variance,
  CASE
    WHEN ABS(g.credit_balance - l.total_liability) < 0.01 THEN 'PASS'
    ELSE 'FAIL'
  END AS status
FROM liquidity_totals l
JOIN gl_totals g
  ON l.report_date = g.report_date;
```

### 阻断规则
- 若 `status = FAIL`，Airflow 任务失败。
- 不允许生成报送文件。
- 触发邮件/企业微信告警。

## 1.6 重述与 SCD2

OWD 表统一增加：

```sql
valid_from_date DATE NOT NULL,
valid_to_date DATE NOT NULL DEFAULT '9999-12-31',
is_current_flag BOOLEAN NOT NULL DEFAULT TRUE,
last_modified_reason VARCHAR(30),
record_version INT NOT NULL DEFAULT 1
```

重述流程：

```text
发现错误
  → 将旧版本 valid_to_date = 修正日 - 1，is_current_flag = false
  → 插入新版本 valid_from_date = 修正日，is_current_flag = true
  → 写入 ads_restatement_log
  → 触发受影响日期重跑
  → Iceberg 保留 snapshot，供审计 Time Travel
```

# 七、最终落地建议

1. **先跑 Core 版**：PostgreSQL + dbt + GE + Airflow，确保 FR 2052a 业务逻辑、GL 对账、校验、报送全部跑通。
2. **再跑 Advanced 版**：Kafka + Iceberg + Spark，展示实时预警、Time Travel、Schema Evolution。
3. **DataHub 最后接入**：先有 dbt 元数据，再摄取血缘和监管映射。
4. **安全不要后补**：PII 脱敏、角色权限、审计日志从第一天就加上。
5. **演示故事线**：  
   “T+1 批处理报送 → GL 对账阻断 → 迟到数据重述 → Iceberg Time Travel 审计 → Kafka 实时流动性预警 → DataHub 监管血缘。”
